# 리플레이 회차 만들기

스포일러 금지 규칙은 `docs/05_AI_RULES.md`의 "블라인드 리플레이 해설"이다. **해설을 쓰는 동안 그 단계 이후의 가격을 보지 않는다.**

## 1. 구간 고르기

1. 사용자가 주제를 주면 그에 맞는 구간을 찾는다(예: 실적 쇼크, 박스권 이탈, 급락 후 반등, 하락장 속 버티기).
2. 후보는 관심 종목의 일봉에서 스크립트로 찾는다. 예를 들어 60일 안에 ±25% 움직임이 있는 지점을 계산한다. 뉴스로 유명한 사건이면 웹에서 날짜를 확인한다.
3. D0(시작일)은 사건 **전**이어야 한다. 앞에 120거래일, 뒤에 60거래일이 있어야 한다.
4. `npx tsx scripts/replay-window.ts --ticker <id> --start <D0 날짜> --check`로 기간이 맞는지 확인한다.

## 2. 단계별 해설 (D+0, 5, 10, 15, … 또는 의미 있는 날만)

각 단계마다:
1. `npx tsx scripts/replay-window.ts --ticker <id> --start <D0> --step <k>`를 실행한다.
2. **그 출력만 보고** 2–4문장을 쓴다.
   - 지금 보이는 것(추세, 거래량, 지지·저항, RSI)
   - 가능한 시나리오 두 가지와 각각을 확인할 신호
   - 연습할 질문 하나("손절선을 어디에 두겠는가?")
3. 금지:
   - 종목명, 날짜, 연도
   - 미래를 아는 듯한 표현("곧", "이후", "결국", "급등할")
   - 실제 결과에 맞춰 해설을 고치는 것

## 3. 공개 글

전체 구간을 본 뒤에야 쓴다.
- 실제로 무슨 일이 있었나(실적, 공시, 업종, 매크로)를 웹에서 조사하고 `sources`에 URL을 단다.
- 결정적 순간이 어느 단계였나, 어떤 신호가 맞았고 틀렸나를 쓴다.
- 해설에서 틀렸던 부분이 있으면 그대로 인정한다.

## 4. 파일

`public/data/notes/replays/<id>.json`:

```json
{ "id": "earnings-shock-1", "title": "종목명 없이, 예: 실적 발표 주간의 갭", "ticker": "KR:000660",
  "startDate": "YYYY-MM-DD", "lookback": 120, "steps": 60,
  "commentary": { "0": "…", "5": "…" },
  "reveal": { "text": "…", "sources": [{ "title": "…", "url": "https://…" }] } }
```

`public/data/notes/replays/index.json`(목록)에 `{ "id", "title", "level": "쉬움|보통|어려움" }`을 덧붙인다.

## 5. 확인과 커밋

`node scripts/check-notes.mjs`가 스포일러 표현과 종목명을 잡는다. 통과하면 `notes: replay <id>`로 커밋하고 `main`에 푸시한다.
